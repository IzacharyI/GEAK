# Reference-only markers for reference_leak_sweep.sh.
#
# Every line is an identifier that (a) the M2.5 reference implementation introduces
# (git diff 8775229e0..<candidate HEAD> over aiter/), (b) the frozen baseline tree never contains, and
# (c) is not mentioned anywhere the run is legitimately allowed to read -- not GEAK_TASK.md, not
# handoff.md, not the state ledger, not knowledge/distributed_fusion.md. So a hit is reference-derived
# bytes, not a word an engineer could have arrived at from the material they were given.
#
# Deliberately EXCLUDED even though the reference introduces them: AITER_MEGAMOE_FUSE_ALL,
# AITER_MEGAMOE_FUSE_COMBINE, AITER_MEGAMOE_FUSE_QUANT, path=MEGA and friends. The task string and the
# positive control name those flags on purpose, so an engineer's own honest candidate will contain
# them; flagging them would make the sweep fire on legitimate work and get switched off.
#
# Bare English words from comments (Deadlock, Together, Announce, ...) are excluded for the same
# reason: they are not evidence.
#
# Also excluded, added 2026-08-21 after they fired on honest work: analysis_no_p2p_payload and
# _analysis_combine_wait_ticks. Both are Step-2 INSTRUMENTATION names -- the no-payload control's env
# flag and the combine-wait cycle counter. They entered the marker list because the derive ran against
# an instrumented reference build, but GEAK's own multi_rank_analysis/derive_*.py scripts read those
# runs and must name the counters. A tool that flags its own evidence pipeline is a tool that gets
# muted, and the design of the fusion cannot be recovered from a counter name.
#
# Regenerate after the reference moves:
#   reference_leak_sweep.sh --derive /root/geak_reference/AITER-candidate <frozen baseline tree>
# then re-apply the two filters above by hand. A stale list silently under-reports.
