# Reference-only markers for reference_leak_sweep.sh.
#
# Every line is an identifier that (a) the M2.5 reference implementation introduces
# (git diff 8775229e0..<candidate HEAD> over aiter/), (b) the frozen baseline tree never contains, and
# (c) is not mentioned anywhere the run is legitimately allowed to read -- not GEAK_TASK.md, not
# handoff.md, not the state ledger, not knowledge/distributed_fusion.md. So a hit is reference-derived
# bytes, not a word an engineer could have arrived at from the material they were given.
#
# Deliberately EXCLUDED even though the reference introduces them: AITER_MEGAMOE_FUSE_ALL,
# AITER_MEGAMOE_FUSE_COMBINE, AITER_MEGAMOE_FUSE_QUANT, path=MEGA and friends. The task string and the
# positive control name those flags on purpose, so an engineer's own honest candidate will contain
# them; flagging them would make the sweep fire on legitimate work and get switched off.
#
# Bare English words from comments (Deadlock, Together, Announce, ...) are excluded for the same
# reason: they are not evidence.
#
# Also excluded, added 2026-08-21 after they fired on honest work: analysis_no_p2p_payload and
# _analysis_combine_wait_ticks. Both are Step-2 INSTRUMENTATION names -- the no-payload control's env
# flag and the combine-wait cycle counter. They entered the marker list because the derive ran against
# an instrumented reference build, but GEAK's own multi_rank_analysis/derive_*.py scripts read those
# runs and must name the counters. A tool that flags its own evidence pipeline is a tool that gets
# muted, and the design of the fusion cannot be recovered from a counter name.
#
# Regenerate after the reference moves:
#   reference_leak_sweep.sh --derive <ref tree> <frozen baseline CLONE with its refs intact> \
#     --given <task dir> --given <knowledge dir> --given <roles dir>
# A stale list silently under-reports.
#
# --given (added 2026-08-23) MECHANISES THE FIRST FILTER ABOVE. It subtracts every identifier that
# appears in the material the run is legitimately handed, so tokens the task text names on purpose stop
# being proposed as markers at all. That filter used to read "re-apply by hand", and a hand-applied
# filter is one a tired operator skips -- skipping it fails OPEN in the loud direction, which is the
# direction that gets a scanner switched off. Confirmed on the 2026-08-23 regeneration: --given removed
# SCATTERED (GEAK_TASK.md tells engineers to print it), read_memrealtime (GEAK_TASK.md names it as
# absent) and out_cache_modifier (the documented 2026-08-21 false positive) with no hand editing.
#
# The second filter is now mechanical too: a token with no underscore, no digit and no internal capital
# is an English word, not an identifier (`grep -vE '^[A-Z]?[a-z]+$'`). That rule and nothing looser --
# it drops Deadlock/Lockstep/Megakernel/Publishing while keeping every snake_case and SCREAMING_SNAKE
# name.
#
# --- 2026-08-23 regeneration: what was added, and what was deliberately left out -------------------
#
# The derive was rerun ref-aware (1030 upstream ref trees subtracted, not just the baseline checkout)
# and produced 385 candidates against the 140 installed. Installing all 385 would have been wrong. The
# surplus falls into three classes and only one of them is evidence:
#
#   A. Reference design internals -- the readiness protocol (_tok_ready, _publish_tok_ready,
#      _peek_tile_payload), the epoch slotting (_S2_EPOCH_SLOT), the fused entry points and emitters,
#      the LDS/storage layout, the claim and transfer counters. 56 of these were MISSING and are added
#      below. This was a real gap: these are the highest-value copy evidence in the whole tree, because
#      they ARE the mechanism -- an engineer who independently derives per-token readiness will not
#      independently coin `_publish_tok_ready` next to `_S2_EPOCH_SLOT` next to `_peek_tile_payload`.
#
#   B. Measurement-harness names -- xgmi_*, amdsmi_*, rank_max_of_*, *_bytes_per_replay,
#      idle_subtracted_*, counter_*, combine_wait_*, p95_ticks, _write_json_report. NOT added, for the
#      reason already given above for analysis_no_p2p_payload: the derive runs against an INSTRUMENTED
#      reference build, GEAK's own evidence pipeline must name these counters, and the design of the
#      fusion cannot be recovered from a counter name. This class is most of the surplus.
#
#   C. Generic and third-party -- LOCAL_WORLD_SIZE, mori_socket_ifname, torch_index, visible_devices,
#      command_argv, json_output, duration_s. Not evidence of anything.
#
# Also still excluded: AITER_MEGAMOE_FUSE_ALL / _FUSE_COMBINE / _FUSE_QUANT. GEAK_TASK.md no longer
# names them (it now says only "behind an env var / config predicate"), so --given no longer removes
# them automatically -- but they remain guessable coinages from AITER_ + MEGAMOE + FUSE, and a false
# positive on an honest candidate's opt-in switch is exactly the failure that mutes the tool. The
# less guessable members of the same family (_FUSE_TOK_READY, _FUSE_S2C, _FUSE_G2_PREF, _FUSE_S2_NW8,
# _FUSE_G2_CHUNK, _FUSE_DIAG_NOPUB, _S2_HALVES, _P2P_WT, _QUANT_R) ARE listed: those encode structure.
#
# The 56 additions were tested before installing, in both directions: 0 of 56 fire on the frozen
# baseline, 0 on wave 7's tree, 0 on wave 8's live workspace, and 53 of 56 fire on the reference (the
# other 3 -- fused_arrival_wait, _all_ranks_true, expert_max_routes -- live in the reference's modified
# op_tests/ harness rather than under aiter/, and are absent from the baseline's op_tests).
#
# Five entries that predate this regeneration are kept although the ref-aware derive does NOT propose
# them: _max_tiles, combine_data_type, fused_combine, ready_base, shared_storage. Three are the
# documented prior-art false positives (the derive is right to drop them and the sweep should be
# reading them as noise); they are retained only so that removing them is a separate, deliberate
# change with its own evidence. Do not treat their presence as endorsement.
